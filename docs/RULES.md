# 축구 규칙 정리와 구현 현황

IFAB 경기 규칙(Laws of the Game)을 기준으로 정리하고, 이 게임이 지금 어디까지 지키는지 적었어요.
출처: 위키피디아의 각 규칙 문서(Kick-off, Throw-in, Free kick, Penalty kick, Offside, Back-pass rule, Corner kick). 정확한 문구는 IFAB 원문을 확인하세요.

범례: ✅ 구현 · 🟡 일부/단순화 · ❌ 미구현

## 시작과 재시작 (Law 8)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 킥오프: 차는 선수 외에는 모두 자기 진영, 상대는 센터서클(9.15m) 밖 | ✅ | 공이 차이기 전까지 상대는 서클 밖에 고정 |
| 킥오프: 공이 움직여야 인플레이, 차는 선수는 다른 선수가 건드리기 전 다시 못 건드림 | 🟡 | 차는 선수는 제자리에서 바로 패스해야 함. "두 번 터치" 반칙은 따로 없음 |
| 골을 먹은 팀이 킥오프, 후반 킥오프는 전반과 반대 팀 | ✅ | |
| 킥오프에서 바로 골 가능 | ✅ | |

## 스로인 (Law 15)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 나간 지점에서, 마지막으로 건드린 팀의 상대가 던짐 | ✅ | |
| 상대는 2m 이상 떨어져야 함 | 🟡 | 공 근처 상대를 밀어내는 정도로만 처리 |
| 스로인 직접 골 불가 (상대 골이면 골킥, 자기 골이면 코너킥) | ❌ | 지금은 스로인에서 바로 들어가면 골로 셈 |
| 스로인 받는 선수는 오프사이드 아님 | ✅ | |
| 파울 스로인(양손/발 위치 위반) | ❌ | |

## 골킥 (Law 16)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 공이 차이기 전까지 상대는 페널티 박스 밖 | 🟡 | 현재는 "공이 박스를 벗어날 때까지" 막고 있어 규칙보다 엄격함. 규칙은 **차서 공이 움직이면** 인플레이 |
| 골킥에서 직접 골 가능 | ✅ | |
| 골킥은 오프사이드 아님 | ✅ | |
| 2026년부터 골킥 5초 지연 시 상대 코너킥 | ❌ | |

## 코너킥 (Law 17)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 수비 팀이 마지막으로 건드려 골라인 밖 → 가까운 코너 | ✅ | |
| 상대는 9.15m 이상 | 🟡 | 코너 수비/공격 배치 AI가 처리 (엄밀한 거리 검사는 없음) |
| 코너킥 직접 골 가능, 오프사이드 아님 | ✅ | |
| 2025년부터 키퍼가 8초 넘게 공을 쥐면 상대 코너킥 | ❌ | 키퍼는 1초 뒤 배급하도록 되어 있음 |

## 프리킥 (Law 13)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 직접 프리킥 (파울) | ✅ | 거리가 가까우면 벽 배치, 사람이 차면 조준 |
| **간접 프리킥** (오프사이드, 백패스, 골키퍼 6초 등) | ❌ | 오프사이드는 상대가 공을 받는 형태로 처리 |
| 상대는 9.15m 이상, 벽 | 🟡 | 벽(3~4명)만 구현 |
| 차는 선수가 두 번 연속 터치 금지 | ❌ | |

## 페널티킥 (Law 14)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 박스 안 파울 → 페널티 | ✅ | |
| 킥 전에는 키커와 키퍼 외 박스/아크 밖 | ✅ | 다른 선수를 박스 밖으로 옮김 |
| 키퍼는 골라인 위에서 방향을 고름 | 🟡 | 키퍼가 한쪽을 고르는 방식(일부러 놓치기도 함) |
| 키커의 두 번 터치 금지 | ❌ | |

## 오프사이드 (Law 11)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 상대 진영에서 공과 두 번째 마지막 수비수보다 앞 | ✅ | `engine.js`의 `offsideLine()` |
| 패스가 나간 순간 기준, 받으면 반칙 | ✅ | 실감 모드에서만 |
| 자기 진영, 동일선상은 아님 | ✅ | |
| 스로인/골킥/코너킥에서는 아님 | ✅ | |
| 상대에게 방해/이득을 얻을 때만 반칙 (공을 받지 않는 경우) | ❌ | 공을 받을 때만 판정 |

## 반칙과 징계 (Law 12)

| 규칙 | 상태 | 메모 |
|---|---|---|
| 거친 태클/뒤에서 태클 → 프리킥 | ✅ | 슬라이딩/뒤쪽 태클은 확률이 높음 |
| 옐로(경고) → 두 장이면 레드(퇴장) | ✅ | 경고 2회 시 퇴장 |
| 레드카드(심한 반칙) | ✅ | 낮은 확률로 직접 퇴장 |
| 박스 안 반칙 → 페널티 | ✅ | |
| **백패스 규칙**: 동료가 발로 준 공/스로인을 키퍼가 손으로 잡으면 반칙 | ✅ | 키퍼는 손으로 못 잡고 발로 처리(곧바로 차 냄). 머리/가슴으로 준 공은 손 사용 가능. `engine.js`의 `gain()`/`contacts()` (kickKind 기록) |
| 득점 기회 저지(DOGSO) 퇴장 | ❌ | |
| 어드밴티지 | ❌ | |

## 멀티플레이 지연 개선 (적용됨)

- 연결을 **제어(신뢰)** / **상태(순서 없음)** 두 개로 나눠서 패킷 하나가 늦어도 뒤 패킷이 막히지 않게 했어요. 상태와 이동 입력은 빠른 길, 시작/골/종료/버튼 입력은 신뢰 길로 보내요.
- 일련번호로 늦게 도착한 옛 패킷은 버려요.
- 손님 자신의 선수는 **입력을 바로 반영(클라이언트 예측)** 하고 방장 위치로 부드럽게 맞춰요 (두 화면 위치 차이 대부분 1m 미만).
- 보간 지연을 네트워크 상태(도착 간격/지터)에 맞춰 45~170ms로 자동 조절해요.
- 화면 오른쪽 위에 핑(ms)이 표시돼요 (손님: 직접 측정, 방장: 손님이 알려 준 값).
